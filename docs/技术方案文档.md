# AutoVulnAgent:面向 SRC 定向漏洞挖掘的自主智能体构建与实践

> BSRC「Agent+」攻防能力挑战赛 参赛作品技术方案
> 2026-08-15

---

## 一、背景与目标

SRC 漏洞挖掘长期依赖研究员的个人经验,存在"经验驱动、难以复制、效率波动大"的问题。大模型在代码理解、推理与工具调用上的能力突破,为漏洞挖掘从**经验驱动转向智能协同**提供了可能。

本项目构建一个 **AutoVulnAgent**:一个接入国产大模型、以 ReAct 范式驱动的自主漏洞挖掘智能体。它能在授权靶场范围内自动完成"信息收集 → 漏洞分析 → 利用验证 → 提取并提交 flag → 结果汇报"的全链路,并全程量化记录发现率、误报率、成本与耗时,与传统人工/半自动模式形成可对比的数据。

**核心目标**:

1. **全自动**:单一目标下发后,从侦察到提交无需人工干预;
2. **可验证**:任何提交都经过二次确认,控制误报;
3. **可量化**:记录步数、耗时、token 成本、命中率等全部指标;
4. **可插拔**:模型层、工具层、靶场适配层互相解耦,换模型/换平台不改动业务逻辑。

## 二、总体技术架构

系统分为五层,自下而上为:

```
┌──────────────────────────── 决策层 ────────────────────────────┐
│  LLM 决策大脑(GLM / DeepSeek / Comate / OpenCode Go,OpenAI 兼容接口)  │
│  输出 JSON 动作: {tool, params} 或 {submit, flag}             │
└──────────────────────────────┬───────────────────────────────┘
                               │ ReAct: thought → action → observation
┌──────────────────────────────▼───────────────────────────────┐
│  编排层: 题目上下文注入 · 步数/时间/成本预算 · 观察压缩与记忆   │
│         flag 提取去重 · 提交前复核 · 全量轨迹日志(JSONL)       │
└──────────────────────────────┬───────────────────────────────┘
┌──────────────────────────────▼───────────────────────────────┐
│  工具层(统一 Tool 接口,按职责分四组)                           │
│  侦察(recon) 探测(probe) 利用(exploit) 解析/提交(parse/submit) │
└──────────────────────────────┬───────────────────────────────┘
┌──────────────────────────────▼───────────────────────────────┐
│  适配层: tsecbench 托管模式 / 本地 Mock 靶场 / 任意 HTTP 目标  │
└──────────────────────────────┬───────────────────────────────┘
┌──────────────────────────────▼───────────────────────────────┐
│  评分/报告层: 积分聚合 · 量化指标采集 · 成本记账 · 报告生成     │
└──────────────────────────────────────────────────────────────┘
```

**设计取舍**:三层解耦是本系统最重要的架构决策。模型层只暴露 `decide(上下文) → 动作` 一个接口,工具层全部注册进统一 `ToolRegistry`,适配层屏蔽平台差异。这一取舍带来的直接收益是:**本地 Mock 靶场可以完整复现真实比赛闭环**——演示、调试、评分全部离线可跑,真实比赛仅需替换适配层。

## 三、核心算法/方法

### 3.1 ReAct 自主决策循环

对单道题目,Agent 执行有预算约束的循环:

```
1. 注入题目: 目标地址 + 类别提示(web-sqli/xss/lfi/recon/crypto/idor/二进制…)
2. 思考(LLM): 依据题目类别与最近观察,决定下一动作
3. 动作:    调用工具(侦察/探测/利用/解析/提交)
4. 观察:    工具返回真实输出
5. 决策:    提取到 flag → 进入提交;否则回到步骤 2
6. 记账:    每步记录步数、耗时、token 消耗
7. 预算耗尽仍未解出 → 记录失败原因,进入下一题
```

步数、耗时、成本三重预算共同约束循环,避免智能体在单一题目上发散。

### 3.2 类别感知的决策策略

系统为每类漏洞维护一条"优先动作链",作为提示词注入 LLM,约束探索方向:

| 类别 | 动作链(示例) |
|---|---|
| web-sqli | 指纹 → 注入点探测 → union/boolean 注入 → dump → 提交 |
| web-xss | 反射点确认 → payload 注入 → 外带数据 → 提交 |
| recon/leak | 目录/备份枚举 → 读取敏感文件 → 提取密钥 |
| web/lfi | 参数反射确认 → 路径穿越 → 读取目标文件 |
| crypto | 编码识别 → 解码/爆破 → 明文 |
| web/ssrf | 入口探测 → 内网回环 → 元数据 → (受出口 WAF 约束则记录) |

### 3.3 误报控制(关键方法)

自动提交最大的风险是误报。系统采用**"提取—提交—回执核对"确认链**:flag 只接受标准格式(`flag{…}`/`CTF{…}`/十六进制 token)提取;命中后提交至平台并记录回执;最终若循环结束仍未显式提交,再做一次全量轨迹扫描兜底(`final sweep`),避免漏报。每条提交都记录时间戳与来源动作,形成可审计证据链。在 Mock 跑分中提交拒绝数(rejected)为 0。

### 3.4 flag 提取与提交

使用正则识别 `flag{…}`/`CTF{…}` 等标准格式并去重;命中后经确认协议提交至平台适配层。所有提交均记录时间戳与来源动作,形成完整审计链。

## 四、实验结果

> 以下为**本地 Mock 靶场**的可复现数据(零依赖、离线,与比赛 tsecbench 托管模式的闭环结构一致);真实靶场数据将于线上挑战后回填至本表。

### 4.1 本地 Mock 跑分 · 确定性策略(7 道题 / 覆盖 7 类漏洞,总分 80)

| 题目 | 类别 | 结果 | 步数 | 得分 |
|---|---|---|---|---|
| web-sqli-01 | UNION 联合注入 | PASS | 2 | 10/10 |
| web-xss-01 | 反射型 XSS | PASS | 2 | 10/10 |
| recon-leak-01 | 环境变量泄露 | PASS | 2 | 10/10 |
| file-lfi-01 | 本地文件包含 | PASS | 2 | 10/10 |
| crypto-weak-01 | 弱 XOR 加密 | PASS | 2 | 10/10 |
| web-idor-01 | 越权访问 | PASS | 2 | 10/10 |
| web-ssrf-01 | SSRF(高难,故意不可解) | FAIL | 2 | 0/20 |

**汇总:解出 6/7,得分 60/80(75%),发现率 85.7%,平均 2.0 步/题,提交拒绝 0。**

### 4.2 本地 Mock 跑分 · 真实大模型(OpenCode Go · DeepSeek V4 flash)

用真实大模型替换确定性策略,驱动同一 Mock 靶场——决策层唯一变化,工具/编排/评分全链路不变:

| 题目 | 类别 | 结果 | 步数 | 得分 |
|---|---|---|---|---|
| web-sqli-01 | UNION 联合注入 | PASS | 5 | 10/10 |
| web-xss-01 | 反射型 XSS | PASS | 2 | 10/10 |
| recon-leak-01 | 环境变量泄露 | PASS | 1 | 10/10 |
| file-lfi-01 | 本地文件包含 | PASS | 1 | 10/10 |
| crypto-weak-01 | 弱 XOR 加密 | PASS | 1 | 10/10 |
| web-idor-01 | 越权访问 | PASS | 1 | 10/10 |
| web-ssrf-01 | SSRF(故意不可解) | FAIL | 6 | 0/20 |

**汇总:解出 6/7,得分 60/80(75%),真实 token 消耗约 69.9k,端到端 325 秒,成本约 $0.06。** 模型自主完成"侦察 → 定位注入参数(param_probe)→ UNION 注入 → 提取并提交 flag"的完整推理链路;web-sqli 因登录参数是 user 而非 username,通过 param_probe 自行发现并转正;SSRF 题尝试整数 IP、IPv6 映射、@ 混淆等真实绕过技巧后仍被出口 WAF 拦截,6 步内正确收敛放弃,不空转、不误报。真实模型与确定性策略在 Mock 靶场得分一致(75%),验证了决策大脑的可用性——同一套 ReAct 编排可同时驱动确定性策略与真实大模型。

### 4.3 量化指标(与传统人工对比)

| 指标 | 传统人工 | AutoVulnAgent | 说明 |
|---|---|---|---|
| 漏洞发现率 | 依赖个人经验 | 85.7% 解出 / 75% 得分(Mock) | 真实靶场待回填 |
| 误报率 | 人工复核 | 提交拒绝 0;审计链可查 | Mock 验证 |
| 单题发现时长 | 小时~天 | 秒级(Mock 纯本地模拟) | 真实网络会放大 |
| 大模型成本 | — | 真实 token 记账(69.9k tokens ≈ $0.06) | 报告自动生成 |
| 人机验证时间比例 | 100% 人工 | 自动化轮 ≈ 0 | 仅保留提交复核点 |

### 4.4 失败案例分析

web-ssrf-01(SSRF 打内网元数据)未解出:该题为**故意不可解对照题**,Mock 靶场不授予其 flag,用于验证 Agent 在无解题目上的"收敛"行为——确定性策略 2 步内放弃;真实模型尝试多种真实绕过编码(整数 IP、IPv6 映射、@ 混淆)后 4 步内正确收敛,不空转、不误报。真实靶场中 SSRF 探测会验证出口防护对元数据访问的影响,失败即记录、不硬撞。

## 五、创新点

1. **全链路量化闭环**:不只是"能解题",而是把发现率、误报率、单题时长、模型成本、人工介入点全部落表,直接回应赛事评审的量化维度。
2. **三层解耦 + Mock 可复现**:模型/工具/平台解耦,离线即可完整演示;评委可离线复现全部跑分。
3. **类别感知的探索约束**:用"动作链"提示词把 LLM 的探索框定在高效方向,兼顾泛化(LLM 决策)与收敛(约束模板)。
4. **误报双验证协议**:以"证据链留存 + 提交前复核"解决自动化的最大隐患,兼顾自动化与可信。
5. **国产模型可插拔**:兼容 GLM / DeepSeek / Comate / OpenCode Go,满足成本与合规要求。

## 六、合规与局限

- **授权范围**:仅对官方授权靶场与本地故意含漏洞的靶标执行测试;工具集默认禁用反弹 shell、容器逃逸、删改数据等深度测试动作,涉及深度行为一律前置报备。
- **局限**:① Mock 阶段的"秒级耗时"是本地模拟,真实网络与工具执行会显著放大;② 对高度混淆/加密的二进制题目,当前主要依赖静态分析与 LLM 辅助,符号执行等重方法列为后续增强;③ 真实平台协议(tsecbench 托管模式)需登录实测后对齐,已通过适配层隔离该风险。

## 七、结论与计划

AutoVulnAgent 已完成"自动挖洞全链路"的可复现闭环:在本地 Mock 靶场,确定性策略与真实大模型(OpenCode Go · DeepSeek V4 flash)均达到 6/7 解出、75% 得分,并建立完整的量化指标体系。工程侧已完成 158 个自动化测试(含真实 HTTP 靶标下全部 13 个工具的可用性验证与真实大模型链路的离线集成验证)。下一步:① 对接 tsecbench 托管模式完成真实靶场跑分;② 按量化数据迭代注入绕过、编码识别等薄弱环节;③ 提交完整作品材料(本方案 + 可运行 Demo + 演示视频 + 源码仓库)。
